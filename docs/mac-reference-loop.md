# Macintosh reference loop

`make reference` creates a fresh, verified System 7.5.5 volume and runs the original
under headless MAME. The checkpoint is `opening-text-1`: the opening cutscene has
finished drawing **“In ancient Persia…”**. Success requires `REFERENCE PASS` from
the host report, not merely a normal emulator exit. The command stops at this
checkpoint; it does not validate gameplay, level transitions, or the entire cutscene.

## Inputs and commands

Source the shared environment through `amiga/env.sh` (Make does this). The local
installation needs MAME 0.289, `hfsutils`, and the shared Python environment.
`MAME` may select another location for the identical pinned emulator binary.
All original/derived inputs and results stay in ignored `ref/` and `tmp/`.

- `manifest/reference-inputs.sha256` pins the local ROM files, Steve Taylor's
  System 6.0.8 and 7.5.5 drive archives, and the locally configured PRAM files.
  The system archives came from the existing Alone in the Dark reference setup;
  the published source is [Steve Taylor's Macintosh downloads](https://www.savagetaylor.com/downloads/downloads-macintosh/).
- The IIci ROM archive is from [Internet Archive's emularity-bios repository](https://github.com/internetarchive/emularity-bios/blob/master/maciici.zip).
  Its four interleaved ROM files also match MAME 0.289's `maciici` ROM SHA-1s.
  Both the archive and extracted files have independent SHA-256 pins here.
- `manifest/reference-tools.sha256` pins the MAME executable. The existing
  runtime-data and shared Macintosh-helper manifests are verified before use.
- `manifest/reference-results.sha256` pins the checkpoint PPM and the ordered,
  normalized original-CODE trap log. No original bytes, images, or traces are tracked.

```sh
make extract-original-data
make reference
make check-reference
```

Each invocation retains a new `ref/mame/runs/<timestamp>-<suffix>/` directory.
For a chosen name, use `python3 tools/run_reference.py --name example` after
sourcing the environment. Existing run directories are refused, never overwritten.
Results include `session.log`, `opening.ppm`, `opening.png`, `traps.txt`, and
`report.json`; the disposable disk, generated byte guards, cfg, PRAM, and recorded
MAME PID remain beside them. Failed runs are retained for diagnosis too.

The installer adapts Alone in the Dark's MacBinary/HFS workflow. It verifies the
96 extracted files, installs both forks of all 32 originals, and reads them back
for byte comparison. Type, creator, Finder fields, and original dates are checked
as well. `hcopy` clears Finder's initialized bit so the fresh folder arranges its
icons; this is the only accepted Finder-field normalization. Existing game folders
are refused. The input archives and extracted source files are unchanged.

## Reference configuration and observations

MEASURED: MAME `maciici`, 68030, 8 MB configured RAM, System 7.5.5, Virtual Memory
off, 24-bit addressing. The `mdc48` card occupies NuBus slot C and supplies the
main 640×480×8 display. The IIci's unused built-in screen remains present.
A fresh system disk's Monitors preferences override PRAM, so every run uses the
original Monitors panel to select the card, 256 colours, and its main-screen role.
The resulting GDevice is checked before launching the game.

| Observation | Measured result |
|---|---|
| Original `Gestalt('vm  ')` | error 0, response 0; Virtual Memory off |
| `Gestalt('proc')`, `('sysv')`, `('mach')` | error 0; responses 4, `$0755`, 11 |
| `Gestalt('mmu ')`, `('addr')` | error 0; responses 3, 4 |
| `Gestalt('a/ux')` | error `$EA52` (−5550), response 0 |
| `SysEnvirons(1)` | error 0; record `$00010009/$07550004/$01010005/$003A8053` |
| `MemoryDispatch` | five selector-2 calls return error 0 before the checkpoint |
| MIDI Manager | original setup branch has input/output flags 0/0; no SoundDispatch selector-4 calls on this route |
| MIDI observation control | SoundDispatch is positively observed, including selector `$000C0008`; this does not establish MIDI Manager availability on other routes |
| Packing | original startup words are 0/1; the original branch skips `PackDataAtStartUp`, with no prompt or packing intervention |
| Copy protection | original `PlayNIS` choice is 7, not its challenge selector 100; `CopyProtectionDialog` is not entered before this checkpoint |
| Seed | original `SetRndSeed` receives `$1234`; its stored seed is checked as `$00001234`, before one original `_Random` call |

The packing observation makes no decision about D9. The reference does not bypass
copy protection or infer behavior on later routes. Its branch probes and observed
SoundDispatch calls provide controls for the negative observations above.

## Evidence and acceptance

The input helper, framebuffer reader, trap-debugger approach, and literal checker
adapt Alone in the Dark at the commit in `manifest/references.tsv`. The launcher
uses the fresh folder at (598,98) and the application filename at (103,113);
transparent pixels in the custom icon are unsuitable click targets.

The line-A dispatcher is byte-checked against locally generated metadata from the
pinned interleaved ROM; no ROM instruction bytes are embedded in tracked scripts. Segment identities come from the live jump
table and original resource headers; selected probes compare live bytes with
metadata generated from the pinned application. Curated probe names are in
`disasm/symbols.csv`, using original CODE-resource offsets including their headers.
This is a narrow reference map, not item 4's static/live census.

The only game-state change supplies the fixed argument at the original
`SetRndSeed` entry; original instructions and their seed assignment execute.
The complete routine is byte-checked before the hook is armed. The capture stops
at CODE 15+$0416, after the original `NISTextDraw` drawing/cleanup, with TEXT
resource `$6978`, string index 1. Its verified picture supplies a separate positive
milestone check. Reaching a probe or waiting long enough alone cannot pass.

IIci low-memory observations use MAME's logical (`readv`) accesses. Framebuffer
reads use physical NuBus addresses: translating that 32-bit video address while
the CPU is in 24-bit mode reads unrelated RAM. The PPM uses the live indexed
framebuffer and card palette, not MAME's potentially older cached screen image.
The corrected capture was visually compared with the emulator's opening scene.

`session.log` retains dispatcher entries, selected nested service returns, and
probe evidence. `traps.txt` retains every observed original-CODE trap in order,
including repeated polling calls, normalized to (segment, resource offset, trap)
and semantic selectors. It omits volatile registers, pointers, ticks, and OS/driver
sites outside the original CODE resources. It is not a full-machine trace.

`make check-reference` requires two independently prepared disks to produce
identical captures and ordered trap logs, both matching the pins. It also runs a
live altered-byte-guard rejection, checks missing milestones/seed/branch evidence,
rejects a changed framebuffer and emulator, and verifies ignored output is untracked.
The gate has passed: two fresh volumes matched the pinned capture and all 50,140
ordered original-CODE trap entries; all rejection controls passed. The final
positive signal is `REFERENCE GATE PASS`. Emulated and host time limits
are failure bounds. Cleanup uses the project's recorded PID and `FSUAE_COMMON`.

## Earlier configurations that cannot serve as this reference

MEASURED on MAME 0.289, `maciix`, 8 MB, `mdc48`:

- The System 6.0.8 drive launches the application, then displays an unimplemented
  trap error. The last application trap is `$AB1D`, QDExtensions, with D0
  `$00160000`. Low-memory system version is `$0607`; the archive identity is
  pinned separately. This is a failure, not a reference pass.
- System 7.5.5 at 256 colours proceeds farther, then fails on `$A05C`,
  MemoryDispatch, D0 2. Its MemoryDispatch and unimplemented-trap table entries
  have the same handler. The original Memory panel shows Virtual Memory Off
  and 8 MB. The IIci succeeds at the same service with Virtual Memory off.

The owner authorized System 7 and a compatible Macintosh model. Apple's
[Virtual Memory Manager documentation](https://dev.os9.ca/techpubs/mac/Memory/Memory-153.html)
explains availability checks and why services can be needed with VM disabled.
The failed configurations were not repaired by skipping original game calls.
